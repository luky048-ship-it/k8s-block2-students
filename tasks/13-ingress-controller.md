# Инструкция. Задание 13 — Ingress: контроллер

**Цель:** познакомиться с ingress-контроллером до правил.

---

## Ход работы

### Шаг 1. Включите addon

```bash
minikube addons enable ingress
kubectl get pods -n ingress-nginx
```

Дождитесь Running у контроллера.

### Шаг 2. Исследуйте

```bash
kubectl get svc -n ingress-nginx
```

Какой у контроллера тип Service? Через что он принимает трафик
снаружи? (Это объясняет, почему остальным сервисам NodePort не нужен.)

### Шаг 3. Запрос без правил

```bash
curl --max-time 5 http://$(minikube ip)/ 2>&1 | head -3
```

(на macOS с docker-драйвером адрес недоступен напрямую — тогда просто
запомните, что контроллер отвечает 404, когда правило не найдено;
проверим это в задании 14.)

## Что сдать в отчёте

Тип Service контроллера и вывод: почему все правила живут в одном месте.
